# M1 report: shell, theme and data foundations

Status: **complete.** 166 tests pass, `flutter analyze` is clean. Verified on Linux (debug build), the Android tablet emulator (1280 dp, plus a 1080x2400 phone profile), in light and dark and at 1.3x font scale. Not yet verified on the Tab S9 (it disconnected before the final pass) or a real phone.

## What exists

| Area | Where | Notes |
|---|---|---|
| Design tokens | `lib/ui/theme/tokens.dart` | Light and dark; `ThemeExtension`; Material `ColorScheme` and `TextTheme` derived in `theme.dart`. |
| Fonts | `assets/fonts/` | Figtree 400 to 700 and Source Serif 4 (static instances cut from the upstream variable fonts), with OFL texts shown on the licenses page. |
| Icons and widgets | `lib/ui/widgets/` | SVG-path icon painter, meaning disc (glyph + colour), tool button, panel surface, dot grid. |
| Adaptive shell | `lib/features/canvas/` | Phone: bottom toolbar, More tray, Extract bottom sheet (3 snap points). Tablet/desktop: tool rail, side Extract panel (resizable on desktop), zoom pill. Left-handed mirror. The canvas itself is a **placeholder specimen**. |
| Library, Settings | `lib/features/library/`, `settings/` | Empty state, document list, theme / finger-draws / left-handed settings persisted in SQLite. |
| Identity and time | `lib/core/` | UUIDv7 ids, Hybrid Logical Clock, device id. |
| Op log and commands | `lib/domain/` | Append-only ops, LWW-per-field `EntityState`, `CommandBus` with undo/redo as new ops. |
| Persistence | `lib/data/db/` | Drift schema v1, `DriftOpStore` (log + snapshot in one transaction), rebuild-from-log, WAL. |

## Tests

- **HLC (8):** round-trip and ordering, frozen and backwards clocks, counter overflow, two-device convergence, drift guard.
- **Materializer (6):** LWW, delete/restore, out-of-order, idempotence, and 25 random shuffles of 120 ops giving identical state (commutative).
- **Commands (7):** undo/redo, grouped undo, redo cleared by new action, append-only log, depth cap, and random sequences over 20 seeds checking every intermediate state in both directions.
- **Persistence (8):** atomic log+snapshot, indexed columns, filters, idempotent replay, snapshot equals rebuild-from-log after random activity (5 seeds), rollback leaves nothing behind, reopen from file keeps data and device id, ink blob round-trip.
- **Schema (1):** a fresh install matches the committed v1 dump.
- **UI:** 42 contrast assertions (AA text and 3:1 non-text, both themes), no-overflow sweeps across 6 window sizes x 3 text scales x 2 themes, layout-follows-window-class, left-handed mirror, 48 dp tool targets, library and settings behaviour, 10 goldens.

## Bugs found and fixed along the way

- Device id was regenerated on every call: a lone integer primary key is a rowid alias, so the column default was ignored. Fixed with an explicit slot and a regression test.
- Extract width clamp threw on a 600 dp window (min greater than max). Fixed.
- Tool labels overflowed at 2x font scale. Labels now stop growing at 1.3x; the tooltip and semantics label carry the full name.
- `sqlite3_flutter_libs` is obsolete under sqlite3 3.x and was removed (M0).
- Tests were rendering text in the Ahem placeholder font, which produced false overflows. `test/flutter_test_config.dart` now loads the bundled fonts.

## Contrast findings (changed DESIGN.md)

- Faint Ink #7d7979 measured 4.09:1 on the panel; darkened to #6f6b6b.
- Meaning colours alone are 1.1 to 2.3:1 against the panel, so swatches are glyph discs (circle, diamond, triangle). A test asserts the colours still fail alone, so the glyph rule cannot silently become unnecessary.

## Known limits and deliberate gaps

Each open item below is owned by a milestone in SPEC §18.1 (undo rebuild R14, predictive back R24, Linux window size R25, real phone R26).

- Goldens render shadows without blur (a test-renderer limit), so the FAB shows a dark ring there that does not appear on a device. They check layout, colour and shape, not exact type weight (the test font loader cannot select weights).
- Undo history is in memory and is not rebuilt from the log on launch (planned for M5).
- Tool buttons, zoom and undo/redo are inert; Import PDF and Copy as Markdown only explain that they are not built.
- Predictive back is enabled in the manifest but not yet exercised on a device.
- Linux: the app runs and creates its database; window minimum size (800x520) is set in the GTK runner but was not resized by hand.

## Clean-up after M1

Removed: `cupertino_icons`, the unused `pdfrx` dependency (re-add at M2; it also pulls a pdfium binary into every build), Source Serif 4 weights 600 and 700 (only 400 is used), four unused icons, `Box.intersects`, `EntityState.updatedHlc`, `Op` JSON helpers, the per-class `kind` constants, `Hlc >=`, and three unused tokens (`fast`, `slow` durations, the index-based `meaningColor`). Kept on purpose: `PdfFiles` and `ViewStates` tables (part of the v1 schema, needed at M2 and M6), `HlcClock.receive` (sync), `CommandBus.undoLabel` and `redoLabel` (for the Undo tooltips), and the `rHighlight` radius (a DESIGN.md token, used by highlights in M2).
